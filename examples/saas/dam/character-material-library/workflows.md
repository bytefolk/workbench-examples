# 业务流程

## 当前主工作台

资产管理员创建或编辑人物，登记素材元数据与使用范围，形成新版本 → 内容创作者输入需求，核对有界规则解析和推荐，修改参数 → 确认人物版本与素材快照后提交 Mock 任务 → 排队/生成/待审核 → 审核人填写意见并通过或驳回 → 成片库保存占位结果及来源。

任务状态：`draft → confirming → queued → generating → review → completed`；失败为 `failed`，未开始任务可 `cancelled`。失败重试创建新记录，不覆盖原任务。真实渠道未配置时不能提交。

localStorage 保留业务数据，刷新后按原时间恢复模拟任务；角色身份本身为演示。授权不全、关键素材缺失、用途不匹配、角色不足、停用人物或未配置渠道均阻止提交。详情保留当时人物版本、素材、输入与渠道快照。

完整状态机及角色操作见 [实现说明](workbench/docs/IMPLEMENTATION.md)和 [领域代码](workbench/src/domain/model.ts)。

## 以下为素材管理简版流程

`demo/` 仍用内存和手动模拟完成；该入口的状态格式与 Persona Studio 分别维护。

## A. 素材准备

素材管理员选人物 → 查看情绪覆盖与素材列表 → 搜索或筛选 → 打开素材详情 → 核对版本与使用范围 → 保留或归档。

人物和产品无真实素材时，原型展示固定合成占位数据。入库、上传和授权登记仅描述接入后流程，不提供会使用户误以为已保存媒体的按钮。

素材状态：`active → archived`。当前原型归档是本次会话内的状态变化；刷新恢复。已归档素材不能成为新任务输入。

## B. 任务准备与交接

制作人员选择人物 → 选择该人物的基础素材 → 选择产品素材 → 选择用途和任务类型 → 填写提示词 → 检查输入 → 创建模拟任务。

每个新任务保存人物、人物素材 ID 与版本、产品素材 ID 与版本、用途、提示词及创建时间。输入不满足时不创建任务：

- 人物或任一输入素材为待确认/受限，拒绝。
- 人物或任一输入素材的允许用途不包含本次用途，拒绝。
- 输入已归档、基础素材属于其他人物或缺少产品，拒绝。
- 数字人或产品试戴生成尚未接入，拒绝并展示原因。

这些检查是演示业务规则，不构成真实授权核验。

## C. 模拟任务

`mock-queued → mock-complete`，由用户点击“模拟完成”推进。终态记录明确没有输出文件和生成结果。输入素材后来归档，历史任务仍保留版本快照。

## D. 真实服务接入后的建议状态

`draft → validated → queued → running → review → approved / rejected`；服务失败进入 `failed`，取消进入 `cancelled`。重试创建新的 attempt 并关联原任务；不能把失败任务直接改成成功。该状态机为设计提议，当前原型未实现。
