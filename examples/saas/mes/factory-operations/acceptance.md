# 验收标准

以下是需要验证的行为，不代表已经通过。实际结果与环境记录在 [验证记录](evidence/verification.md)。`npm run check` 验证代码、构建和仓库契约；真实登录、权限、数据库回读和文件预览还需要连接环境检查。

| 编号  | Given / When / Then                                                                                                                      | 检查方法                                  |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| AC-01 | 给定未配置数据提供方，当打开工作台时，应显示配置说明且不生成演示业务记录。                                                               | 浏览器，空配置构建                        |
| AC-02 | 给定有效身份服务，当注册、确认邮件（如要求）并登录时，应得到真实会话；退出后不能继续读写受保护数据。                                     | 连接环境、浏览器及未登录 API 请求         |
| AC-03 | 给定两个不同工作区及其成员，当读取单据、拜访和资产时，只能访问所属工作区；猜测其他 ID 也被拒绝。                                         | 两个测试账号、直接接口请求                |
| AC-04 | 给定工厂角色，当提交完整业务字段和现场照片时，应真实保存单据及资产引用；刷新后可读回。缺失必填项或断针没有照片时应拒绝，耗材允许无附件。 | 浏览器主链路、数据库回读、自动领域测试    |
| AC-05 | 给定待审批单据，当主管批准并推进配送时，状态按顺序变化并形成时间线；操作员直接调用审批接口应被拒绝。                                     | 浏览器、接口权限测试                      |
| AC-06 | 给定配送中的断针单据，当未确认回收就完结时，应拒绝；确认回收并添加备注后才能完结。耗材不需要断针回收。                                   | 自动领域测试、真实数据库状态机检查        |
| AC-07 | 给定待审批单据，当主管拒绝时，应保留原因和历史，拒绝后不能继续配送。                                                                     | 状态机测试、浏览器                        |
| AC-08 | 给定同一单据的旧版本，当另一个成员已推进状态后再提交旧版本时，应报告冲突且不覆盖最新版本。                                               | 并发 API 请求                             |
| AC-09 | 给定同一状态操作请求 ID，当网络重试提交两次时，不应产生重复状态事件。                                                                    | 请求重放、时间线计数                      |
| AC-10 | 给定销售角色，当保存拜访后应刷新可读回；销售只能查看本人拜访，主管和所有者可查看全工作区，操作员不能读取。销售不能审批工厂单据。         | 浏览器、角色 API 测试                     |
| AC-11 | 给定工作区资产，当有权限的成员预览时应取得可用授权地址；其他工作区或未登录用户不能读取私有文件。                                         | 文件上传/下载、权限请求                   |
| AC-12 | 给定上传失败、连接中断或身份过期，当用户操作时，应显示错误，不能显示虚假成功；无法确认服务端是否已保存时，刷新回读后再重试。             | 错误注入、浏览器                          |
| AC-13 | 给定合法 HTTP 提供方配置，当以相同业务契约执行身份、单据、拜访和资产操作时，前端可使用该接口；配置不完整或服务未实现时不能标成已连接。   | HTTP 适配器测试与部署者服务联调           |
| AC-14 | 给定干净检出，当执行安装、检查和构建时，应通过 schemas/索引一致性检查；统一目录可找到 MES 案例并打开工作台。                             | `npm ci`、`npm run check`、目录浏览器检查 |

当前范围不包括企业 SSO、AI 语音与图片识别、钉钉通知、ERP 库存扣减或客户正式验收。HTTP 客户端通过测试不等于企业 MySQL 服务已经部署；每个提供方必须单独形成连接证据。

## 整包交换扩展验收

| 编号  | Given / When / Then                                                                                                                                 | 检查方法                           |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| AC-15 | 同工作区完整快照经过导出、预览和恢复，报告、拜访、事件版本、原操作者、请求记录、来源与资产清单保持一致，不重放业务动作。                            | 领域测试、数据库事务测试、部署回读 |
| AC-16 | 空模板、范围内漏表、重复键/ID、未知列、非法整数/真实日期、悬空引用或缺回收/照片的完成记录，应整包拒绝并返回表/行/字段；最后一行错误也不能部分发布。 | 领域负例、服务端直接请求及回读     |
| AC-17 | 显式空表显示准确删除数量，范围外表保留且共同参与候选校验；不能删除报告却留下旧事件，空 tables 不清库。                                              | 候选库与数据库回滚测试             |
| AC-18 | 预览后有人新增、审批、上传登记或修改数据，旧目标 revision 提交失败；同 requestId 重试同计划返回同结果，不同内容复用 ID 拒绝。                       | 事务/并发测试、HTTP 错误注入       |
| AC-19 | 非所有者直接请求导出、预览或提交被拒绝；所有成员仅可读取当前工作区来源元信息。                                                                      | 服务端角色与工作区测试             |
| AC-20 | 跨工作区包、未知/改写或包内业务未声明的资产拒绝；备份后新增无关资产不阻止恢复，候选库保留当前全部资产；旧资产回读失败时不伪造完整快照。             | 领域测试、资产适配器与部署检查     |
| AC-21 | 上传照片只保存资产并生成合成待核对草稿；编辑确认后仍保留 synthetic/mock/reviewed。生成至预览间版本变化须重新核对，不能覆盖其他成员写入。            | 领域与浏览器测试                   |
| AC-22 | 只有服务端发布成功后刷新来源及版本；失败保留原正式数据，切换工作区/连接后旧响应不串入新页面，模拟记录往返后继续标注。                               | 浏览器竞态和失败注入               |
| AC-23 | 超过 5 MiB、40 层或业务注册上限的输入明确拒绝；HTTP 保留原文、同幂等键，不自动重试 403/409/服务或网络失败。                                         | 解析边界与 HTTP 契约测试           |

新增功能的本地验证、云端回滚事务与真实用户 UI 验收分开记录。个人试用 Supabase 交换迁移已部署并完成数据库与权限检查，当前千问托管试用站已发布；静态资源、未登录入口和邮箱确认回跳已验证。邮箱确认开启，默认/显式目标的 303 回跳与精确允许列表匹配；真实用户登录后的 UI 和文件存取仍待按下列步骤验收。此前 Sites 403 属于历史访问记录。其他提供方不能继承此 `connected` 状态；通用 schema、领域测试和客户端契约不能替代数据库事务与真实提供方验证。

## 真实存储与登录后验收操作

以下是待执行的验收手册；结果应记录在 [验证记录](evidence/verification.md)，不能把操作步骤本身记为通过。

1. 使用应用账号完成所需的邮箱确认并登录，创建名称明确的专用合成验收工作区。后续操作始终确认当前工作区，使用合成文件与业务字段。
2. 准备一张小于 20 MiB 的合成 JPEG、PNG 或 WebP 图片，保留原文件并记录文件名、字节大小与 SHA-256。通过资产或申领上传入口上传，确认资产登记完成且列表出现对应记录；仅文件传输成功不能代替登记成功。断针申领必须包含照片，PDF 不能代替现场照片。
3. 将该资产关联到一条合成申领，保存后检查列表与详情只出现预期单据和附件引用。若提示失败或回包不确定，先刷新回读确认是否已保存，再决定是否重试，避免重复创建。
4. 从已登记资产取得预览/下载入口，确认可用，并将下载文件的大小与 SHA-256 和原文件比较。授权地址有时效，保留资产引用即可，不把临时签名地址放入公开验收记录。
5. 刷新页面，然后退出并重新登录，重新选择同一工作区；确认单据、附件登记与关联仍存在，并重新获取下载入口再次读取相同文件。预览、下载及重新登录回读全部成功，才能记录本轮真实存储链路通过。
6. 由工作区所有者导出当前 JSON，保存后在该专用工作区内进行一次受控修改，再预览并恢复原快照。核对变更数量、业务记录与附件引用，确认附件仍可读取。此恢复只针对同工作区业务 JSON；包中只有资产元数据与引用，没有文件正文，不能恢复已丢失的文件，也不能作为跨提供方迁移或全量备份。
