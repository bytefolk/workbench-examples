# 业务流程

## 进入工作区

部署者配置数据提供方后，用户通过邮箱注册或登录。若所选身份服务要求邮件确认，完成邮件确认后再登录。已登录用户可以创建工作区或进入已有工作区；新工作区创建者成为所有者。只有所有者可添加已注册且确认邮箱的成员，角色由服务端校验。

未配置服务时显示配置说明；连接失败时显示失败原因，数据列表不伪装成空白成功。没有工作区或记录时显示真实空状态。切换工作区后重新读取该工作区的数据。

## 工厂上报到完结

1. 操作员、主管或所有者选择“断针”或“耗材”，填写合同号、物料编号、工位、原因、数量，并上传现场照片等证据。断针至少关联一张 JPG、PNG 或 WebP 照片，耗材附件可选。
2. 资产上传成功后得到持久资产引用；提交申领时关联这些引用。表单缺少必要信息，或断针没有照片时不能提交。
3. 单据进入 `submitted`（待审批）。主管或所有者查看照片、业务字段与历史，填写备注后批准或拒绝。
4. 批准进入 `approved`（待配送），再由主管或所有者推进到 `delivering`（配送中）。
5. 耗材配送完成后可进入 `completed`（已完结）。断针还须先执行回收确认；未回收的断针禁止完结。
6. 每次处理记录操作者、时间和备注，详情中可按时间线回看。完结或拒绝的单据不再继续推进；修改原因或重报时创建新单。

| 当前状态                | 允许的下一状态         | 前置条件                                   |
| ----------------------- | ---------------------- | ------------------------------------------ |
| `submitted`             | `approved`、`rejected` | 当前工作区主管或所有者，有效版本和操作备注 |
| `approved`              | `delivering`           | 当前工作区主管或所有者，有效版本和操作备注 |
| `delivering`            | `completed`            | 当前工作区主管或所有者；断针已回收         |
| `completed`、`rejected` | 无                     | 终态，保留历史                             |

回收确认是独立业务操作，不通过直接更新字段绕过流程。它只针对尚未回收的断针，由主管或所有者处理并留下备注；允许在 `submitted`、`approved` 或 `delivering` 阶段确认，终态不能再处理。

## 销售拜访

销售、主管或所有者填写客户名称、拜访时间、沟通纪要、问题、下一步以及可选跟进日期，保存为该工作区的拜访记录。主管与所有者可查看本工作区全部拜访；销售仅可查看自己创建的记录，操作员不可读取拜访。刷新和再次登录后从服务端读取。纪要由使用者编写；当前没有自动录音转写或模型生成。

## 附件与资产

业务记录持久保存资产 ID 和资产元信息，文件正文进入配置的资产存储。预览时由资产服务签发短时访问地址，不把签名 URL 写入单据或公开文档。上传成功不等于业务单据提交成功；提交失败时应根据提示核对结果后再操作，已上传附件可在资产列表查看。

## 失败与并发

- 权限不足：服务端拒绝，界面说明当前角色不可操作，原记录保持不变。
- 版本过期：其他成员已修改单据时拒绝旧版本；刷新详情后再决定操作，避免覆盖最新状态。
- 重复动作：同一请求 ID 用于识别重放；客户端重试应沿用该 ID，服务端防止重复事件。
- 网络或文件上传失败：显示错误，允许用户重试；不能显示已保存或插入本地假记录。
- 会话失效：要求重新登录，不能以本地角色切换绕过权限。
- 普通单据页面没有撤销或删除操作；所有者可通过受控整包替换恢复业务表，显式空表的删除影响必须在预览中确认。整包恢复不重放通知等外部动作。

## 整包导出、预览与恢复

仅所有者使用“数据接入”。导出读取当前一致快照，包含四张业务表和完整资产清单；登录信息、成员与文件正文不进入包。选择本工作区的 JSON 原文后，服务端检查重复键、注册契约、严格字段、最终引用、来源、事件链和资产清单，返回逐表数量与删除影响。

读取文件和预览均不改变正式数据。明确确认后按计划 ID、目标 `expectedRevision` 和提交 `requestId` 原子发布；预览后有其他写入时旧计划冲突退出。响应丢失可沿用原请求 ID 重试确认，同一计划不会重复发布。恢复历史状态不重新执行原来的审批命令或通知，保留原事件操作者及请求记录。

工厂档案必须包含且 ID 等于当前工作区。范围外业务表保留；范围内漏表报错，显式 `[]` 表示清空该表，但不得留下悬空事件。当前界面选择四表全量范围；包内资产是已登记资产的有效子集，传入行引用必须由包声明，范围外保留行按当前清单验证。恢复保留当前全部资产，不删除或搬运备份后新增的文件。空格式模板只能下载参考，不能执行。

## 拍照核对与来源

1. 所有者选择申领或拜访台账，上传 JPG/PNG/WebP 原图到当前资产平台。保存照片不表示业务记录已发布。
2. 本地模拟器基于当前快照生成固定合成草稿，不读取图片文字；新申领仅为待审批，不能由照片触发完结或回收。
3. 对照原图编辑草稿，勾选人工核对，再预览完整候选库。生成后工作区版本变化须重新生成与核对，避免覆盖其他成员更新。
4. 确认替换并收到成功回执后，业务页和来源条重新从服务端读取。草稿保持 `synthetic + mock + reviewed`，人工确认不消除模拟标识。

切换工作区或连接后丢弃原页面请求结果，禁止用旧预览提交到新工作区；预览失败不更新来源标签。不支持交换服务的提供方显示未支持，仍可使用原有业务页面。
