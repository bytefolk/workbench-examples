# MUSE 缪思 品牌数字人技术验证工作台

面向品牌内容创作人员，演示图片资产、候选确认、脚本、任务和成品复用。当前为 **prototype**：免费模拟闭环可运行；有可配置的 Higgsfield / Qwen 适配代码，但没有真实账号回执或客户生成质量验收，不能称为 integrated。

默认人物、商品、图片与样片全部虚构。6 秒内置样片只是图片动态示意，没有 AI 表演或声音克隆。现有 Persona Studio 案例保留，差异见 [两套工作台对比](comparison.md)。

## 从干净检出启动

需要 Node.js 22.12+。从仓库根目录执行：

```sh
npm ci
npm run check
npm run demo
```

打开 http://127.0.0.1:4173 ，选择 MUSE。目录入口只运行模拟，不能连接本机代理或产生付费请求。全部资源位于自己的构建目录，浏览器存储键为 `bytefolk-brand-digital-human-studio-v1`，与 Persona Studio 隔离。

## 演示步骤

1. 在资产库搜索、筛选、收藏或上传一张图片；支持 PNG/JPEG/WebP，最大 2 MB。
2. 新建视频，输入「让苏遥戴着 S002 围巾，在午后窗边介绍商品」，点击推荐品牌资产。
3. 检查候选编号、更新时间和理由，确认后应用；没有自动覆盖原选择。
4. 编辑规则分镜后提交模拟生成，约 22 秒后完成；任务可筛选、取消或重试。
5. 成品库预览内置 6 秒样片、审核、下载、导出配置并复用。模拟时长选项不代表样片实际时长。

侧栏重置只清本案例浏览器记录，不取消平台请求或删除 Soul ID；不要用它处理正在执行的真实任务。当前没有企业账号、多用户共享和永久媒体归档。

## 独立运行接口验证

从仓库根目录执行：

```sh
npm run dev --workspace muse-digital-studio
```

打开 http://127.0.0.1:4318 ，同时启动 127.0.0.1:8788 本机代理。不开配置时不调用收费模型。Vite 开发与预览入口可代理 API；仓库 4173 的目录入口始终只模拟。

将 `workbench/.env.example` 复制为同目录 `.env`，只在该文件填写密钥；随后重启独立服务：

```dotenv
HF_API_KEY=完整的API密钥
HF_ENABLE_REAL=true
API_PORT=8788
```

先确认账号权限、余额和素材授权；服务端有配置不代表账号验证通过。费用估算会上传参考图片但不创建视频任务。视频、人物身份创建和参考图生成可能收费，本案例不包含额度。不要把配置、素材、平台结果地址或运行记录提交到 Git。

人物参考流程为照片 → 同账号 v2 Soul ID → 等待 completed → Soul 2 新参考图 → 确认后用于视频。不是向任意视频模型直接提交 Soul ID。Demo 创建最多 12 张照片，每张 2 MB；此软件限制不是高保真素材保证。

当前视频合同为 Seedance 2.0 多素材参考和 Kling O3 多图参考。分镜编译为一条短片提示词，不做逐镜生成、长片拼接、独立声音克隆或口型同步。全身动作、同人物表情和商品细节需真实样片验收。详见 [接入说明](integrations.md) 和 [验收](acceptance.md)。

Qwen 为可选，使用当前工作空间对应的 `DASHSCOPE_API_KEY`、`QWEN_BASE_URL` 和 `QWEN_MODEL`，按 Token 计费。不配置时使用免费规则检索。代理运行记录存于忽略目录 `workbench/.local/higgsfield-demo/`，不是生产数据库。

## 可交付与限制

正式 B 类可建设客户自用工作台、共享资产库、账号、队列、存储及交接；这些并未在当前 Demo 全部完成。自有素材、配置、成品和工作台源码可以另定导出及交接范围；Soul ID 不等于可导出的人物模型。零漂移、商品零误差、平台永远可用或退出后凭模型继续生成不承诺。

对比建议：现阶段用 MUSE 验证 Higgsfield 生成链路，同时借鉴 Persona Studio 的版本、授权、角色和审核流程。两套都不是已经满足完整数字人质量门槛的生产产品。
