# 企业数字人资产与视频生成工作台 PRD

## 1. 文档目的

本 PRD 用于指导开发 Agent 实现一套可交互的最小工作台 Demo，证明“企业人物资产可统一管理，并可在生成视频时被自动复用”的核心流程。

本阶段重点是工作台、资产平台与任务编排，不承诺自行训练底层数字人模型，也不宣称已满足全身剧情生成能力。

## 2. 项目背景

本案例面向服饰与配饰领域的虚构品牌，用于演示人物资产复用和内容制作流程。品牌希望将真人形象、声音及历史素材沉淀为长期数字资产，用于商品种草、试戴展示、生活方式短片和剧情内容。

现有问题是：使用各类 AI 视频平台时，员工每次都要重新上传人物照片、基础视频、音频和人设，素材分散、准备重复、人物一致性难控制，也缺少统一的权限、版本和归属管理。

因此需要建设企业内部资产库，并衔接一个 AI 视频生成入口。员工只需描述内容需求，系统即可找到适合的人物资产并创建生成任务。

## 3. 产品目标与边界

### 3.1 产品目标

1. 将人物照片、视频、音频、声线、人设、动作样本和授权材料统一沉淀为企业资产。
2. 让员工通过自然语言或结构化表单快速发起视频生成任务，无需重复上传人物资料。
3. 根据需求自动推荐人物资产、生成配置和可用模型，并保留人工确认环节。
4. 统一查看生成进度、结果、历史版本、费用估算和调用记录。
5. 为后续接入真实第三方模型 API、权限审批和私有化部署预留清晰接口。

### 3.2 本期范围（MVP Demo）

- 人物资产列表、搜索、筛选、详情和新增。
- 图片、视频、音频等素材元数据管理。
- 自然语言生成入口和结构化生成参数。
- AI 模拟解析需求，推荐人物、场景、情绪、动作和模型。
- 任务确认、模拟提交、状态流转和结果归档。
- 基础角色权限和操作记录展示。
- 模型渠道以可配置适配器形式展示，首版允许使用 Mock Provider。

### 3.3 明确不做

- 不在本期训练或交付真实数字人模型。
- 不保证人物一致性、全身动作、服饰细节和口型同步达到商用标准。
- 不实现直播。
- 不实现真实支付、计费结算和正式合同管理。
- 不实现 A、B、C 三种商业交付模式的完整后台，仅在方案信息中展示。
- 不将通用 Agent 数字员工与本项目的真人虚拟形象混为一体。

## 4. 用户角色

| 角色       | 核心诉求                   | 主要权限                               |
| ---------- | -------------------------- | -------------------------------------- |
| 内容创作者 | 快速选人、写脚本、生成视频 | 浏览可用资产、创建任务、查看本人任务   |
| 资产管理员 | 维护人物及素材质量         | 新增、编辑、上下架资产，维护授权和版本 |
| 审核人     | 控制品牌一致性和内容风险   | 审核生成配置与成片，驳回或通过         |
| 系统管理员 | 管理成员、模型和平台配置   | 全局配置、权限、模型渠道、审计记录     |

## 5. 核心业务流程

1. 资产管理员创建人物档案。
2. 上传或登记照片、视频、音频、声线、动作样本、人设及授权材料。
3. 系统标记资产完整度、可用状态、版本和使用范围。
4. 内容创作者输入需求，例如：“用品牌主理人形象生成一段秋季帽子试戴短片，语气克制温柔，30 秒”。
5. 系统解析需求，推荐人物、声线、场景、动作、比例、时长及模型渠道。
6. 用户核对或调整配置，提交生成任务。
7. 任务经过“草稿 → 待确认 → 排队中 → 生成中 → 待审核 → 已完成/失败”状态流转。
8. 审核人查看结果并通过或退回。
9. 成片及其脚本、参数、人物版本、模型渠道和生成记录被统一归档，可再次复用。

## 6. 信息架构

### 6.1 首页

- 核心指标：可用人物数、素材数、进行中任务、待审核任务、本月生成次数。
- 快捷入口：新建生成任务、新建人物资产。
- 最近任务、热门人物和异常提醒。

### 6.2 人物资产

- 卡片/列表视图。
- 按名称、标签、状态、授权范围和负责人筛选。
- 人物详情包含：基础信息、人设、形象素材、声音资产、动作/表情样本、授权信息、版本记录、关联成片。
- 资产状态：草稿、待补充、可用、停用、授权过期。

### 6.3 视频生成

- 自然语言需求输入区。
- 推荐人物与资产摘要。
- 可编辑参数：脚本、场景、情绪、动作、商品、画幅、时长、语言、声线、模型渠道。
- 资产缺口提示和风险提示。
- 提交前配置确认。

### 6.4 生成任务

- 任务列表与状态筛选。
- 任务详情：输入需求、解析结果、人物版本、模型、进度、费用估算、结果、失败原因和操作日志。
- 支持复制任务、重新生成、取消未开始任务和发起审核。

### 6.5 成片库

- 成片预览、筛选、标签和版本管理。
- 展示来源任务、人物版本、脚本及模型信息。
- Demo 可提供模拟下载按钮，不要求真实视频文件。

### 6.6 管理设置

- 成员与角色。
- 模型渠道配置。
- 资产标签与分类。
- 审核规则。
- 操作审计。

## 7. 功能需求

### F1 人物资产管理

- **FR-001** 系统应支持创建、编辑、查看和停用人物档案。
- **FR-002** 人物档案至少包含名称、头像、简介、标签、负责人、状态和使用范围。
- **FR-003** 系统应支持登记图片、视频、音频、声线、动作、表情、脚本及授权文件等素材类型。
- **FR-004** 每份素材应记录类型、来源、上传者、创建时间、版本、授权状态及备注。
- **FR-005** 系统应计算并展示资产完整度，缺失关键素材时不得标记为“可用”。
- **FR-006** 系统应保留人物资产版本；历史任务必须关联当时使用的版本。
- **FR-007** 用户只能查看和使用其权限范围内的人物资产。

### F2 智能需求解析

- **FR-008** 用户可用自然语言描述视频需求。
- **FR-009** 系统应将需求解析为人物、用途、商品、场景、情绪、动作、脚本、时长和画幅等字段。
- **FR-010** 系统应推荐匹配的人物资产并解释匹配依据。
- **FR-011** 当需求缺少关键字段或资产不足时，系统应明确提示，不得静默猜测关键授权或人物身份。
- **FR-012** 所有 AI 推荐均允许用户修改后再提交。

### F3 视频任务编排

- **FR-013** 用户可从解析结果创建生成任务。
- **FR-014** 提交任务前应展示人物版本、使用素材、模型渠道、参数和费用估算。
- **FR-015** 任务状态至少支持：草稿、待确认、排队中、生成中、待审核、已完成、失败、已取消。
- **FR-016** 系统应记录每次状态变化的时间、操作者和原因。
- **FR-017** Demo 应提供可控的模拟生成流程，能演示成功与失败两种结果。
- **FR-018** 模型调用应通过 Provider Adapter 抽象，前端不得依赖某一家模型的专属字段。
- **FR-019** 失败任务应展示失败原因并允许复制原配置重新发起，不能自动无限重试。

### F4 审核与成片管理

- **FR-020** 生成结果可进入人工审核。
- **FR-021** 审核人可通过或驳回，并填写意见。
- **FR-022** 成片库应记录结果与人物、任务、脚本、参数和模型的关联关系。
- **FR-023** 用户可复制历史任务形成新草稿，但不得覆盖原任务记录。

### F5 权限与审计

- **FR-024** 系统应实现内容创作者、资产管理员、审核人、系统管理员四类角色。
- **FR-025** 高风险操作包括停用人物、修改授权范围、删除素材引用和修改模型配置，应记录审计日志。
- **FR-026** Demo 中若不实现真实登录，必须提供角色切换器清楚演示不同权限，且标注为演示能力。

## 8. 数据模型建议

| 实体              | 关键字段                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------- |
| Character         | id、name、avatar、profile、tags、ownerId、status、scope、currentVersionId                   |
| CharacterVersion  | id、characterId、version、changeNote、createdBy、createdAt                                  |
| Asset             | id、characterId、versionId、type、name、url、source、licenseStatus、metadata、createdBy     |
| GenerationRequest | id、rawPrompt、parsedRequirement、createdBy、createdAt                                      |
| GenerationTask    | id、requestId、characterVersionId、providerId、config、status、estimatedCost、failureReason |
| GenerationResult  | id、taskId、previewUrl、fileUrl、duration、resolution、reviewStatus、createdAt              |
| Review            | id、resultId、reviewerId、decision、comment、createdAt                                      |
| Provider          | id、name、capabilities、configSchema、enabled、mode                                         |
| AuditLog          | id、actorId、action、targetType、targetId、before、after、createdAt                         |

开发可按实际技术栈调整，但必须保留人物版本、任务、结果和审计之间的可追溯关系。

## 9. 非功能需求

- **NFR-001 易用性**：首次使用者应能在 3 分钟内从首页创建一个模拟生成任务。
- **NFR-002 响应式**：优先桌面 Web，最低支持 1280px 宽度；移动端只要求基本可读。
- **NFR-003 性能**：普通列表和详情页在本地 Demo 数据下应在 1 秒内完成可见内容渲染。
- **NFR-004 可追溯性**：任务必须能追溯至人物版本、素材、脚本、参数和模型渠道。
- **NFR-005 安全**：任何 API 密钥不得写入前端代码或示例数据。
- **NFR-006 可替换性**：Provider Adapter 应允许后续接入多个模型渠道。
- **NFR-007 诚实呈现**：Mock 结果、费用和模型能力必须明确标识，不能包装成真实商用能力。

## 10. Demo 数据与交互要求

Demo 至少预置：

- 3 个人物资产：品牌主理人、成熟生活方式女性、虚拟品牌模特。
- 每个人物包含不同完整度和授权状态，用于演示提示与拦截。
- 3 个模型渠道：一个可用 Mock、一个配置缺失、一个停用。
- 6 个历史任务，覆盖生成中、待审核、完成和失败状态。
- 4 个成片占位结果，覆盖商品试戴、生活方式独白、剧情独角戏和种草短片。

关键演示链路：

1. 切换为内容创作者。
2. 输入“用品牌主理人生成 30 秒秋季帽子试戴短片，温柔克制，竖屏”。
3. 系统解析并推荐人物、声线、场景和动作。
4. 用户确认配置并提交。
5. 任务进入模拟生成，随后进入待审核。
6. 切换审核人，通过结果。
7. 在成片库查看归档结果及完整溯源。

## 11. 验收标准

### 11.1 必须通过

- 能完整跑通上述七步演示链路。
- 人物资产、素材、任务、结果和审核信息可查看且相互关联。
- 缺授权或资产不完整的人物不能直接提交生成任务。
- 用户可以修改 AI 解析结果。
- Mock 任务可稳定演示成功和失败。
- 四类角色权限在界面上有清晰差异。
- 页面无明显空壳入口；不可用能力应说明原因或隐藏。
- 不包含任何真实密钥和客户敏感素材。

### 11.2 不作为本期验收

- 真实模型生成质量。
- 真人形象建模和克隆声线效果。
- 全身动作、试戴、复杂剧情和多机位质量。
- 私有化模型文件交付。
- 正式报价和商业合同。

## 12. 技术实现约束

- 可使用开发 Agent 熟悉的 Web 技术栈，优先选择便于快速演示和后续扩展的方案。
- 数据首版可使用本地 JSON、SQLite 或轻量数据库；需要保证刷新后数据仍存在时再选持久化方案。
- 模型调用必须经统一服务层，不允许页面组件直接调用外部模型。
- 建议定义 `generate(config)`、`getTask(id)`、`cancelTask(id)` 和 `getCapabilities()` 等 Provider 接口。
- Demo 可以使用本地定时器模拟任务状态推进，但状态机应集中管理，不能散落在多个组件中。
- 所有模拟能力应有 `Mock` 标识。

## 13. 风险与待确认事项

| 事项                   | 当前处理                                                                       | 后续确认人/条件                                              |
| ---------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------ |
| 客户主体与案例发布范围 | 不作确定结论                                                                   | 售前确认客户公司全称                                         |
| 常用 AI 视频平台及 API | 用户确认使用小云雀，短剧方向；已查到官方 API 文档，Demo 继续使用 Mock Provider | 验证客户账号调用权限、企业人物及声线素材复用、实际价格和样片 |
| 全身剧情与试戴能力     | 工作台仅记录能力标签                                                           | 由底层模型供应商提供样片验证                                 |
| 人物建模最小素材规范   | 暂用通用素材分类                                                               | 模型供应商给出具体规格                                       |
| 资产及模型归属         | 在档案中预留字段                                                               | 商务与法务确认 A/B/C 交付条款                                |
| 预算、并发和时效       | 不进入本期承诺                                                                 | 客户访谈后补充                                               |
| 真实审核流程           | 先做单级审核                                                                   | 客户确认是否需要多级审批                                     |

## 14. 后续阶段

- **阶段 1：可交互 Demo**——完成本 PRD 范围，验证需求和工作流。
- **阶段 2：真实 API POC**——接入一个已验证的视频生成渠道，用非敏感测试资产跑通。
- **阶段 3：客户试点**——加入真实权限、审核、计费和素材规范，完成样片验收。
- **阶段 4：生产化**——多模型路由、稳定性、成本治理、资产退出和私有化能力。

## 关键假设

- 本次交付目标是供售前展示和需求验证的本地工作台 Demo。
- 已确认客户使用小云雀短剧平台，并查到官方短剧 API 文档；尚无客户账号实调用、真实价格或生成质量验收证据。
- 客户最关注的是资产长期复用、人物一致性、自由驱动和资产归属；工作台负责管理与编排，底层模型负责生成质量。
