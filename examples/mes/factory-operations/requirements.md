# 需求与范围

## 来源与边界

2026-10-14 根据已读取的业务听记及后续架构要求抽象整理。公开仓库不保存听记链接、逐字稿、真实客户、联系人或附件。本文中的业务名称与数据均为合成示例，尚未获得完整客户验收。

已知需求：

- 工厂员工通过照片上报断针、物料与耗材需求，关联合同号、物料编号、工位和原因，方便后续追溯。
- 主管审批后进入配送，处理完成后结束；断针必须确认回收后才能完结。
- 销售记录客户拜访、沟通纪要、问题、下一步和跟进日期。
- 用户需要真实登录，业务数据和附件进入部署者选择的数据库与资产平台。
- 每个部署者可选择不同数据源。Supabase 是本次部署选择，案例库不能把业务模型绑定到 Supabase；MySQL 等实现通过标准接口接入。

## 本次 MVP

| 范围         | 交付约定                                                                     |
| ------------ | ---------------------------------------------------------------------------- |
| 身份和工作区 | 邮箱登录/注册、创建和选择工作区、工作区成员与角色                            |
| 工厂申领     | 带照片的断针或耗材上报，检索合同/物料/工位，审批、拒绝、配送、回收确认和完结 |
| 留痕         | 状态版本校验、操作备注和时间线，拒绝越权与非法状态变更                       |
| 销售拜访     | 新建及查看拜访记录、纪要、问题、下一步与跟进日期                             |
| 资产         | 上传文件到所选资产存储、保存资产引用、授权预览                               |
| 数据源       | 标准身份/业务/资产端口，Supabase 适配器、企业 HTTP 适配器及接入契约          |

产品划分采用一个主 MES 场景，销售跟进作为跨领域流程，使用 CRM 标签发现。首次注册不等于加入其他工作区；成员需要由该工作区管理员添加。

## 实现提议

以下是根据需求选择的 MVP 方案，尚不代表业务方确认：

- 以工作区作为数据隔离边界，定义所有者、主管、操作员、销售四类成员。
- 所有者通过已注册且确认邮箱的账号添加成员；外部邀请、企业目录同步与单点登录另行实现。
- 以 `completed` 表示已完结，断针回收是完结的前置条件，单独保留回收事件。
- 部署时选择 `supabase` 或 `http`；用户也可在当前浏览器连接设置中覆盖默认配置。同一服务内的用户通过工作区隔离；直接填写数据库密码、跨租户越权或自动迁移不在本次范围。
- MySQL 由企业服务端实现 HTTP 契约，浏览器仅访问受认证的业务接口；数据库凭据留在服务端。现有资产平台也可经同一接口实现文件上传与授权下载。

## 未纳入本次交付

钉钉消息通知、AI 自动总结或语音识别、图片识别、ERP 库存扣减、采购付款、GPS 拜访打卡、财务核算、MySQL 直连适配器和历史数据自动迁移均未接入。应用不把这些能力标成已连接，也不以模拟记录代替真实写入。

## 后续待确认

1. 断针回收的现场证据、回收人及双人复核要求；是否需要独立安全管理员。
2. 配送签收是否由申领人确认；拒绝后是重新提交新单，还是保留原单修订。
3. 现有合同、物料、客户主数据的权威来源及编号校验规则。
4. 企业资产平台接口、文件保留年限、归档与删除策略。
5. 后续部署采用的身份系统、数据库、资产存储，以及组织范围、备份和运维责任。
