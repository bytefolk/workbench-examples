# 台账整包交换契约 v1

状态：**通用参考契约，含工厂案例实现**。本文、[JSON Schema](../schemas/ledger-package.schema.json) 和 [空模板](../templates/ledger-package/README.md) 定义交换边界；[工厂工作台](../examples/saas/mes/factory-operations/README.md) 实现了下述受限范围。通过 schema 只证明包的结构，不代表业务有效、已连接服务或可以提交；实际部署证据单独记录。

## 包格式与业务注册契约

交换包包含 `schemaVersion`、`packageKind`、`packageId`、`datasetContract`、`dataRevision`、`metadata`、`exportScope`、`tables` 和 `assets`。包内不携带登录凭据、成员授权或目标数据库配置。

| 字段            | 含义                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------- |
| schemaVersion   | 交换格式版本；本提案为 1，不兼容版本必须拒绝或显式迁移                                      |
| packageKind     | template 为不可执行空模板；snapshot 为准备导入或导出的数据包                                |
| packageId       | 包标识；正式包使用新标识，不能用模板标识或把它当作提交请求 ID                               |
| datasetContract | `{id, version}` 引用案例的 dataset registry 契约；unknown/unassigned 不能提交               |
| dataRevision    | 导出源的一致快照版本；模板为 null。它不等于目标当前版本                                     |
| tables          | 逻辑表名映射为行数组，每行是 `{id, data, provenance}`                                       |
| assets          | 稳定资产引用清单，包含 ID、名称、类型、大小、SHA-256 和 `{storeId, objectId}`；不含文件正文 |

exportScope 声明 `{completeness: full | partial, tables: [...]}`，表名须与包内 tables 完全一致。full 表示源数据集声明表的全部业务行，不代表未列出的表；角色过滤或条件筛选后的导出必须为 partial。partial 包不能用于表级或整库 replace，若需导入应另行定义合并契约。模板的 exportScope 为 null。

dataset registry 由各案例实现，必须明确：允许和必需的表、字段 schema、ID 唯一范围、枚举、日期及数值精度、跨表引用、流程约束、分析/行动记录、资产规则、导入权限和数量上限。它决定具体台账模型；此通用 schema 不硬编码 ERP 表，也不把库存流水转换成耗材申领。工厂身份由该契约的工厂档案及工厂 ID 引用承载，metadata.label 仅供显示。预览须列明来源工厂到目标工厂的映射及冲突，不能靠同名或包内标识自动覆盖其他工厂；目标工作区仍由当前会话确定。

数字和日期按字段契约严格处理：禁止自动把空白或非法数字变为 0、截断小数、丢失前导零的标识或默默换算单位。超出安全整数范围的数值、金额和精确小数采用契约声明的十进制字符串或最小单位整数。日期须检查真实年月日和时区规则，不能接受自动滚动成下个月的日期；schema 的时间戳正则只检查外形。JSON 重复对象键、重复行 ID 均报错，禁止采用“最后一条覆盖前一条”。

## 来源与识别记录

`metadata.contentOrigin` 为 synthetic、user-imported 或 mixed；`metadata.storage` 为 local 或 shared，描述导出源的存储环境。二者独立：示例数据可以存入共享服务，本机数据也可能来自用户文件。导入目标由当前连接和工作区确定，不能由包内 storage 改写。导入合成文件后仍是 synthetic，不因经过用户上传变成真实工厂数据。

每行的 `provenance.contentOrigin` 保留行来源。曾经过识别的行还保留 `recognition: {mode, reviewStatus, sourceAssetIds}`：mode 为 mock 或 connected，reviewStatus 为 unreviewed 或 reviewed。**人工确认只改变复核状态，不把 mock 改为 connected，也不删除原识别来源。** 元信息必须与行来源汇总一致；混合包不能一律标成工厂数据。

全页来源条读取当前已发布数据集，至少表达名称、来源性质和本机/共享范围；识别草稿另标模拟及待核对。导入成功后才更新来源与版本；失败、切换工作区或收到旧请求响应时，不能把新标签挂到旧数据上。

## replace：先形成最终候选库

replace 只接受已验证完整范围的 full 快照；不能只信任包自报 full，导出器与接收端须按注册契约核对范围及来源。预览请求显式绑定目标工作区、`mode: replace`、`replaceScope` 和包。replaceScope 是此次替换的逻辑表集合，必须非空、属于注册契约，且与包内 tables 的表名集合完全一致。

- 范围外的表保留；范围内漏表是错误，不等于删除。显式 `[]` 表示把该表替换为空，预览必须显示删除数量。
- 全数据集替换要求范围覆盖注册契约声明的所有业务表，包括流程事件、分析、行动与其关联，不能只导入页面主表。
- `tables: {}` 是空模板或无操作输入，不能用来清空工作区。assets 清单也不是删除资产库的命令。
- 在内存或暂存区构造“未替换旧表 + 新表 + 已验证资产映射”的最终候选库，再校验全部引用和业务约束。例如保留的行动不能引用被替换掉的分析，已完成断针不能缺少回收事实与照片。

校验错误统一返回 `{table, row, field, code, message}`；field 使用 JSON Pointer，row 使用从 1 开始的输入行号；包级 table/row 或保留数据的 row 可为 null，可额外给出 recordId。预览列出各表替换前后数量、删除影响、错误和警告，不写正式数据。原始行号应保留，不能先去重或丢掉坏行再展示“通过”。

## 提交、原子性与导出

交换能力是独立的可选 `LedgerExchange`：`getDatasetState(workspaceId)`、`exportSnapshot(workspaceId)`、`previewImport(workspaceId, {packageText, mode, replaceScope})`、`commitImport(workspaceId, {planId, expectedRevision, requestId})`。预览保留 JSON 原文到可信服务端，避免客户端先解析丢失重复键。IdentityProvider、OperationsRepository、AssetStore 的职责保持独立，交换服务通过部署适配器协调它们，不绑定特定数据库。没有此能力的提供方明确显示未支持，不通过前端循环写入替代。

预览结果 planId 绑定包摘要、契约版本、替换范围、目标工作区和目标数据版本。提交时再次确认授权与契约有效性，并以 expectedRevision 检查并发：预览后其他成员新增、审批或修改数据，旧计划应冲突退出，不能覆盖其结果。所有影响候选库的正常写入也必须推进目标版本；只检查单条单据 version 不足以保证整包替换。

同一 requestId 在该工作区重试同一计划只返回同一结果；用于不同包或范围时报冲突。一次数据库事务发布业务表、引用、导入结果和新 revision。任何校验或提交失败都保留旧版本，不能通过前端循环删除/创建来实现。响应丢失时可按 requestId 查询或重放确认结果，不能另起请求重复导入。

文件正文先通过资产适配器准备并校验大小、类型和摘要，再原子发布引用。数据库与对象存储不共享事务，因此失败时允许有未发布暂存文件，但不能出现业务引用缺文件或提前删除旧文件。跨提供方导入必须完成稳定 ID 映射及字节校验；不能把 storagePath 或临时签名 URL 当作可移植资产。此 JSON 只是数据与资产清单，单独文件不构成自包含备份。

导出由服务端或支持事务的本地适配器读取同一 revision，并声明导出范围；角色过滤后的局部列表不能冒充完整备份。export → import 应保留业务字段、流程状态与事件、分析、行动、关联和来源，不重新生成演示内容或重放通知、付款等外部动作。ID 变更需有完整映射；历史操作者作为来源引用保留，不能冒充当前用户的新审批。现有案例是否允许恢复历史状态，由其业务契约决定，通用导入不能绕过受控状态机。

## 拍照台账适配器

`POST /api/vision/ledger` 仍是拟议 HTTP adapter 契约，当前没有可调用的 OCR 服务。工厂工作台已提供 **mock** 拍照核对流程：保存照片、生成固定规则的合成草稿、对照原图编辑、人工确认，再走相同预览与提交；模拟器不读取照片内容。真实实现需另行验证并声明 connected，不通过改按钮文案升级能力。

建议请求 `{workspaceId, assetId, ledgerType, requestId}`，返回 `{draftId, schemaVersion, mode, sourceAssetId, rows, warnings}`。rows 保留原图位置、识别值和缺失字段。服务端校验资产可读性；地址来自部署配置。识别只产草稿，经用户核对后送入同一预览/提交流程；照片中的“完成”“付款”或“回收”文字不能自动触发对应业务动作。保留识别来源，人工复核不消除 mock 标记。

## 工厂案例已实现的范围

注册契约为 `factory-operations` v1，业务表为 `factory`、`reports`、`report-events`、`visits`。工厂档案始终包含在范围内，ID 必须等于当前工作区；当前界面导入和导出四表全量快照。完整字段见 [工厂数据模型](../examples/saas/mes/factory-operations/data-model.md)。这不是完整 ERP 台账，不接受未声明的库存、采购或财务表。

- 仅工作区所有者执行导出、预览和提交；新提供方仍需在服务端实现这些权限。JSON 最大 5 MiB、嵌套最多 40 层，每表最多 10000 行；UUID、字段、日期、整数、枚举、事件状态链和引用均严格校验。
- 仅同工作区恢复，包内资产清单必须是当前已登记资产的有效子集，逐项元信息、稳定引用和 SHA-256 一致；传入业务行所用附件及识别原图必须在包中声明。候选库保留当前全部资产，范围外保留行按当前清单校验，备份后新增的无关资产不阻止恢复。文件正文留在原资产平台，成员、登录信息和连接设置不随包替换；不能用这份 JSON 完成跨工作区或跨提供方迁移。
- 普通快照可恢复旧业务状态，但必须通过当前数据的预览和并发检查；不会重放审批或通知。照片模拟草稿额外绑定生成时快照版本，生成后已有成员更新时必须重新生成和核对，不能覆盖中间写入。
- 来源从业务行汇总，`factory` 档案不参与合成/用户提供的汇总。已有同 ID 记录的来源、识别模式及原图引用不可通过替换改写；人工确认保留 mock 与 synthetic。
- 空格式模板依旧不可执行。需要真实字段骨架时先导出当前工作区；新增申领/拜访还必须满足事件、历史操作者与资产规则，不能只填页面主表。

客户端领域与 HTTP 契约已有针对性测试。个人试用所选 Supabase 项目已应用 `20261014171026` 交换迁移，并通过 8 组云端回滚事务与权限检查；具体范围见 [案例验证记录](../examples/saas/mes/factory-operations/evidence/verification.md)。这些数据库检查不等于真实用户的云端 UI 验收，首次应用注册尚待使用者完成。Sites 所有者私有试用站已发布，Supabase 已连接；真实用户注册后的 UI 验收待完成。本机静态预览已验收，当前网络访问线上站点被托管边缘拦截，未进入工作台；其他提供方仍须独立接入与验证。

## 最小验收

1. 合法快照往返后，流程、分析、行动及其引用不丢失，来源与资产摘要保持一致。
2. 最后一行错误、重复 ID、无效日期/数值、悬空引用或非法状态，整包零发布，并定位到表/行/字段。
3. 范围内漏表拒绝，范围外旧表保留，显式空表准确展示删除影响；空模板不能提交。
4. 预览后并发写入导致冲突；同 requestId 重试不重复写入，不同内容复用 ID 被拒绝。
5. 文件失败、事务失败、提交响应丢失时无半包可见，旧版本保持可读并能确认最终结果。
6. mock 识别经过人工确认与导出再导入后仍保留 mock 来源；切换工作区后旧响应不能串入当前页面。

实施时同步案例规格、能力声明和证据，遵守 [案例规范](case-standard.md) 与 [提供方契约](data-provider-contract.md)。这些标准材料不增加已运行案例或已接通能力的数量。
