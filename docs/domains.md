# 工作台分层分类

目录按 **服务模型 → 业务族 → 领域** 定位能力，在领域中按 **标准主干 → 场景变体 → 实际案例** 查找可复用设计与实现。行业、角色和部署方式是独立信息，不为每种组合复制一个分类或空案例。

SaaS、PaaS、IaaS 的概念依据应用、平台与基础设施的职责划分。微软官方说明分别以业务应用、应用开发运行平台，以及计算、存储和网络资源描述这三层。参见 [Microsoft Azure：IaaS、PaaS 与 SaaS](https://azure.microsoft.com/en-us/resources/cloud-computing-dictionary/what-are-iaas-paas-and-saas)。

本库使用这三个名称标记工作台的**目标能力层**，不表示源码模板已被托管为云服务。部署在本机、自托管或公共云，以及采用哪个身份、数据库和资产提供方，独立于业务分类。下面的 **60 个 SaaS 领域、8 个 PaaS 领域、5 个 IaaS 领域** 是本库为发现与复用制定的组织约定，既不是官方完整分类标准，也不是已交付产品数量。

## 分类与复用数据

| 文件                                                  | 当前内容                                      | 作用                                         |
| ----------------------------------------------------- | --------------------------------------------- | -------------------------------------------- |
| [service-models.json](../catalog/service-models.json) | 3 个服务模型                                  | 标记目标应用、平台或基础设施层               |
| [domain-groups.json](../catalog/domain-groups.json)   | 12 个业务族：SaaS 10 个，PaaS 与 IaaS 各 1 个 | 组织同类业务能力，便于浏览                   |
| [domains.json](../catalog/domains.json)               | 73 个领域，版本 3                             | 定义工作台的主要业务对象与边界               |
| [blueprints.json](../catalog/blueprints.json)         | 22 个标准主干                                 | 保存角色、实体、流程、页面和扩展点的参考设计 |
| [variants.json](../catalog/variants.json)             | 44 个场景变体，每个主干 2 个                  | 说明行业或业务情境带来的具体差异             |
| [cases.json](../catalog/cases.json)                   | 3 个实际代码案例                              | 索引实现、交付状态和运行证据                 |

业务族 ID 与领域 ID 全局唯一；每个领域只归属一个服务模型和一个业务族，二者的服务模型必须一致。案例路径仍为 `examples/<serviceModel>/<domain>/<case>/`；业务族与复用关系通过目录数据表达，不增加重复目录层。主干和变体不自带运行声明，关系和新增方式见 [案例复用资产](case-assets.md)。

## IaaS：5 个基础设施领域

本层统一归 `infrastructure-resources` 业务族，关注资源的配置、容量、连接与恢复。容器领域指集群、节点和配额等基础设施管理；容器中运行的业务应用不会自动归入该类。跨层平台仍按工作台主要管理对象判断。

| ID           | 领域               | 收录边界                                 |
| ------------ | ------------------ | ---------------------------------------- |
| `compute`    | 计算资源           | 虚拟机、计算规格、镜像与资源配额         |
| `storage`    | 存储资源           | 对象、块与文件存储的容量、访问与生命周期 |
| `networking` | 网络资源           | 虚拟网络、子网、负载均衡与网络连接       |
| `containers` | 容器与集群基础设施 | 容器集群、节点、命名空间与基础资源配额   |
| `backup`     | 备份与灾难恢复     | 备份策略、恢复点、恢复任务与灾备演练     |

## 相邻领域的选择规则

- **综合协同与专门流程**：跨订单、采购、库存、财务的资源交接归 ERP；只做采购执行归采购管理。跨供应、生产、交付的异常协调归 SCM；单独做需求预测或排程分别归需求计划、APS。
- **客户收入链**：CRM 管商机关系，CPQ 管单笔配置报价，定价管理管可复用价目与策略，OMS 管订单履约。订阅管计费与权益周期，收入确认管财务履约义务。客服管请求解决，现场服务管上门执行，客户成功管采用价值与续约风险。
- **供应与物流**：SRM 管供应商关系和资格，采购管请购到采购订单，库存管理管库存账和可用量，WMS 管库位作业，TMS 管货运过程，车队管自有车辆生命周期。
- **人力与财务**：HRM 保留员工主档与入转调离，招聘、考勤、薪酬、人才发展和学习各有独立闭环。财务与费用保留应收应付和结算协同，报销、资金、会计、税务、收入确认与预算计划分别按专门对象收录。
- **设计与生产**：PLM 管设计基线，PIM 管面向销售渠道的商品表达，MES 管现场执行，QMS 管质量处置，LIMS 管样品检测过程；一个检验流程可引用实验室报告，不必复制成两个案例。
- **资产与内容**：DAM 管可复用数字素材，EAM 管自有设备维护，设施管理管空间与现场服务，不动产管理管房产租约。IaaS 存储管存储资源；使用对象存储不改变 DAM 或 MES 分类。
- **协作与治理**：项目协作管理一个项目的交付，PPM 管多个项目的优先级和容量。GRC 管持续风险控制，审计管独立检查与取证；合同管理管审签与履约义务。业务审批优先归业务领域，通用行政服务才归 OA。
- **分析与平台**：BI 面向业务指标和分析行动，MDM 面向业务黄金记录与分发；PaaS 数据工程面向采集、加工、编排和治理技术。ITSM 管服务流程，DevOps 管构建交付平台，IaaS 管底层资源。

选择主领域时，以主要用户每天完成的核心任务为准；跨域能力用 tags 和集成关系说明。跨领域扩展只在需要独立业务闭环时拆成新案例，不按页面数、技术栈或数据库数量拆分。
