# 工作台分层分类

统一目录按 **服务模型 → 领域 → 案例** 展开。先判断工作台面向业务应用、开发平台还是基础设施，再判断它主要管理的对象。每个案例只有一个服务模型和一个主领域，跨领域通过 tags 发现。

SaaS、PaaS、IaaS 的概念依据应用、平台和基础设施之间的职责划分；云厂商可组合提供这些能力。微软的官方说明将 SaaS 描述为可直接使用的应用，PaaS 为构建与运行应用的平台，IaaS 为计算、存储和网络等基础资源。参见 [Microsoft Azure：IaaS、PaaS 与 SaaS](https://azure.microsoft.com/en-us/resources/cloud-computing-dictionary/what-are-iaas-paas-and-saas)。

本库把这些概念用于描述案例的**目标应用层、平台层或基础设施层**。这不表示仓库模板已由 ByteFolk 托管成云服务。实际部署可以是本机、自托管或公共云，数据提供方另行选择。下面的 22 / 8 / 5 个领域是本库的组织约定，便于发现和复用，不声称是唯一行业标准或完整产品清单。

## 一级服务模型

| ID     | 分类                  | 主要使用者           | 工作台关注的对象                 |
| ------ | --------------------- | -------------------- | -------------------------------- |
| `saas` | SaaS · 业务应用       | 业务人员与业务管理者 | 客户、订单、工单、内容及协作流程 |
| `paas` | PaaS · 开发与数据平台 | 开发、平台与数据团队 | 应用构建、运行、集成和数据能力   |
| `iaas` | IaaS · 基础设施       | 基础设施与运维团队   | 计算、存储、网络、集群和备份资源 |

机器可读定义分别在 [service-models.json](../catalog/service-models.json) 与 [domains.json](../catalog/domains.json)。领域 ID 全仓库唯一，每个领域归属一个服务模型。实际案例由 [cases.json](../catalog/cases.json) 索引，目录采用 `examples/<serviceModel>/<domain>/<case>/`。

## SaaS：22 个业务应用领域

| ID          | 领域               | 主要业务对象                       | 可收录的工作台方向   |
| ----------- | ------------------ | ---------------------------------- | -------------------- |
| `crm`       | 客户与销售 CRM     | 客户、联系人、商机、跟进           | 销售跟进、商机推进   |

| `hrm`       | 人力资源 HRM       | 员工、招聘、入职、绩效             | 招聘入职、人员服务   |

## PaaS：8 个开发与数据平台领域

这里管理的是供其他应用使用的平台能力。例如托管数据库属于 PaaS 能力的一种，而使用数据库的业务工作台仍按它自身的业务目标分类。参见 [Microsoft Learn：Azure SQL Database 的 PaaS 定义](https://learn.microsoft.com/en-us/azure/azure-sql/database/sql-database-paas-overview)。

| ID              | 领域               | 主要平台对象                           | 可收录的工作台方向 |
| --------------- | ------------------ | -------------------------------------- | ------------------ |
| `app-platform`  | 应用开发与运行平台 | 应用、运行环境、发布、应用生命周期     | 应用部署与运行管理 |
| `dbaas`         | 数据库服务 DBaaS   | 托管数据库实例、连接、容量、数据库运维 | 数据库实例运营     |
| `baas`          | 后端服务 BaaS      | 应用身份、数据接口、函数、后端能力     | 后端项目配置与管理 |
| `integration`   | 集成与接口平台     | 连接器、接口、事件、数据交换           | API 与集成任务管理 |
| `low-code`      | 低代码开发平台     | 表单、数据模型、流程、应用编排         | 应用搭建与发布     |
| `devops`        | DevOps 与交付平台  | 代码集成、流水线、制品、发布环境       | 构建与发布管理     |
| `ai-platform`   | AI 开发平台        | 模型接入、推理服务、评测、AI 应用开发  | 模型服务与评测管理 |
| `data-platform` | 数据工程平台       | 数据采集、加工、编排、目录、治理       | 数据管道与治理管理 |

## IaaS：5 个基础设施领域

本层聚焦资源本身的容量、配置、连接和恢复。容器领域指集群、节点和资源配额等基础设施管理；在容器中部署的业务应用不会自动归到这一类。微软的三模型说明也将 CaaS 列为 IaaS 的扩展；实际平台产品可能跨层，仍按案例的主要目标判断。

| ID           | 领域               | 主要资源对象                     | 可收录的工作台方向     |
| ------------ | ------------------ | -------------------------------- | ---------------------- |
| `compute`    | 计算资源           | 虚拟机、计算规格、镜像、配额     | 计算资源申请与运营     |
| `storage`    | 存储资源           | 对象、块、文件存储容量与访问     | 存储资源与生命周期管理 |
| `networking` | 网络资源           | 虚拟网络、子网、负载均衡、连接   | 网络配置与连通性管理   |
| `containers` | 容器与集群基础设施 | 集群、节点、命名空间、基础配额   | 集群资源运营           |
| `backup`     | 备份与灾难恢复     | 备份策略、恢复点、恢复任务、演练 | 备份与恢复管理         |

## 分类边界与已有案例

- CRM 以客户关系和销售跟进为主；客户服务以请求受理与解决为主。
- ERP 涉及整体资源与订单；MES 聚焦现场执行；QMS 聚焦检验和质量闭环；PLM 聚焦设计与工程版本。
- SCM 关注供需与交付协调；SRM 聚焦供应商关系；WMS 聚焦仓内作业；TMS 聚焦运输过程。
- DAM 管理可复用的数字内容；EAM 管理设备及其维护；IaaS 存储管理容量、存储对象和访问资源。
- SaaS 的 BI 面向业务指标与分析结果；PaaS 数据工程面向采集、加工、治理和对外数据能力。
- ITSM 的核心是 IT 服务流程；IaaS 的核心是基础设施资源。DevOps 领域聚焦构建和交付平台。
- [Persona Studio](../examples/saas/dam/character-material-library/README.md) 归 `saas/dam`，营销与生成相关能力使用 tags；它的本地模拟交付状态不改变分类。
- [工厂运营工作台](../examples/saas/mes/factory-operations/README.md) 归 `saas/mes`，销售拜访通过 `crm` 标签关联。Supabase 是身份、数据库与资产的后端选择，不会让工厂工作台改归 `paas/baas`。

行业、角色、技术与部署方式也可以用 tags 描述，如 `manufacturing`、`sales-manager`、`dingtalk`、`self-hosted`。同一案例只有一个主路径；跨层依赖记入 `integrations.md`，不复制成多个案例。

上述“工作台方向”是分类示意，不计入已交付案例。尚无案例的类别只保留字典和首页空状态，不创建空案例目录。概念来源核对日期：2026-10-14。
