# factory-smart-ops 数据接入复核

复核日期：2026-10-15。对象：[公开演示](https://factory-smart-ops.app.workbuddy.host/)及当时页面加载的 `assets/index-2hWI45UD.js`。这里只记录公开页面和已发布前端的行为，不代表已审查其源代码仓库、后端或真实工厂数据。

方法：浏览页面确认交互和能力标注；将公开构建产物中的校验、转换、导入与导出函数隔离，用合成数据在离线环境复现。没有向演示站导入、清空或修改业务数据。以下结果针对该版本；构建产物行号不是源码行号，因此不用于 PR 行级评论。

## 值得复用的设计

- 同一入口提供整包模板、导出、导入预览和逐行错误，方便迁移与交接。
- 拍照先生成草稿，再由人核对，最后进入与手工导入相同的业务校验流程。
- 各页面保持可见的数据来源条，帮助用户识别示例与导入内容。

这些设计已抽象到 [台账交换与识别接入约定](ledger-exchange.md)。该约定是参考设计，不能据此宣称现有案例已实现整包导入或真实 OCR。

照片入口当前明确标为模拟识别；已发布前端调用本地模拟函数。页面列出的 `POST /api/vision/ledger` 可以作为未来 adapter 接口，但仅展示契约不能证明 HTTP 服务已经接通。本次未验证后端是否存在，也未评估真实识别质量。

## 接入本仓库的条件

以 [案例规范 v3](case-standard.md)、现有标准主干和场景变体为准。数据库、身份、资产存储采用各案例声明的端口；本机选择 Supabase 不应成为所有用户的固定依赖。

工厂耗材、换件和异常处理可对齐 `mes-production-operations / garment-workshop-consumables`。如果另做订单、采购、库存、结算等完整业务，应评估 `erp-order-resource-coordination` 下的独立变体，避免把所有业务塞进现有 MES 记录模型。

提供源码分支或 PR 后，再核对实现、依赖、合成 fixtures、失败与重试、并发提交、往返一致性和浏览器验收。没有源码与可复现证据时，公开 demo 作为设计参考，不直接计作已交付项目案例。公开文档只保留抽象需求，不复制原始私人对话。

建议验收顺序：先修复最终快照校验与往返丢失，再修复来源、重复 ID 和数值约束；通过自动验证后，验证替换预览、失败不写入和人工核对交互。真实 OCR 的连接状态与质量应单独验收。
